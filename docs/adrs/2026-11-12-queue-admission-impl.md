# Per-job admission on a station's queue: the built version

## Status

Accepted. Builds `2026-11-12-event-core-queue-admission.md` (which keeps the decision) and refines its details.

## Context

A pipeline's trains carry batches; a job whose precondition fails (QA, a dependency, a ticket state) must not board and must not block the others. The earlier ADR chose a script on the station's queue. This one records what was built, and where the requirements of the first user (a monorepo pipeline with `stg` and `prd` stations that checks a code host) changed a detail.

## Decision

1. **Format**, a block in the station's `queue:` (`.agents/skills/extend-playbook-format`): `queue: { mode: fifo | merge, admit: { script: admit_x.sh, poll: 10m, wake_on: [{ types: [...], filter: {...} }] } }`. `script` is an executable of the folder's `scripts/`; `poll` is required (the safety net); `wake_on` has the rules, validation and types of the script step's (`2026-11-12-script-wake-on.md`). Only on a singleton's station; a flat `admit` on a step is refused and says to write it under `queue:`. The first station may have one like any other.
2. **Not a step.** The check is not in a train: no run, no manager, no agent, no tokens. The runtime runs it like a script check (one in flight per station queue, dirty flag, 5 s minimum gap, a check cut by a restart runs again, so the script must be idempotent) and kills it after 5 minutes (a failure).
3. **Triggers.** The first look when jobs wait (also after a daemon restart), the `poll` timer, the station's `wake_on` events, and **always** `job.queued` of its own pipeline for this station, which users do not write. A human's "Check again" runs it at once, ignoring the gap. A queue with nothing to check (no waiting job that a human did not admit) costs no check and no timer; it starts again with the first job. The events its own check causes (`job.held`, `job.admitted`, `job.escalated` of this station) never wake it: this is the own-events rule of the script wake-up, scoped to the station.
4. **Working directory.** The pipeline run's `workspaceDir`: the shared checkout its trains use, since there is no train and no worktree. The script path is read there. A missing script is looked up once more after refreshing the workspace when no train runs (the branch may have it); a missing workspace or script, or a failure, fails the check visibly and changes nothing.
5. **Input** (environment): `PLAYBOOK_JOBS`, JSON list of the station's waiting jobs, oldest first, each `{ id, label, since, inputs }` with all the job's own inputs; `PLAYBOOK_STATION`, `PLAYBOOK_PIPELINE` (the playbook id), `PLAYBOOK_RUN_ID` (the pipeline run), `PLAYBOOK_STEP_ID` (the station), `PLAYBOOK_CHECK`, `PLAYBOOK_WORKSPACE`, `PLAYBOOK_JOBS_OMITTED`. Bounded: at most 100 jobs and 100,000 characters (an environment variable has an OS limit), always at least one job, string inputs cut at 10,000 characters; the jobs over the cap are not looked at (nor held) until a later check, and their count is `PLAYBOOK_JOBS_OMITTED`. Jobs a human admitted anyway are not listed.
6. **Result**: the last stdout line, a JSON object (the keys may also sit under `outputs`): `admit: [ids]`, `hold: { id: reason }`, `escalate: { id: reason }`. A job given to the check and not named is **held** with "not admitted by the script". A job named twice takes the strictest verdict (escalate, hold, admit); an id that was not given is ignored with a warning (kept on the station's status). Exit 75, a failure, a timeout or an unreadable result (no JSON line, wrong types) changes nothing; the next trigger retries. This refines the earlier ADR's "not admitted by <script>" reason.
7. **State.** A waiting entry has `held: { reason, checkedAt } | null` (default null: older run files load unchanged) and `forced: boolean` (default false). A job that joins a station with `admit` starts held with `checkedAt: null` ("waiting for its first admission check"): nothing boards before the script has spoken, which is the earlier ADR's rule for a station with an `admit` block. `held` changes only when the verdict or its reason changes, and `checkedAt` is when it was decided; a script that holds for the same reason every poll writes nothing and sends nothing. A later check may hold an admitted job that has not boarded; a job a train retries (its train failed) waits again admitted. `forced` is set when a human admits the job: later checks neither hold it nor list it. `nextTrainJobs` skips held entries **before** `fifo`/`merge` apply (a held oldest job never blocks fifo); only a station that has `admit` honours a hold, so removing the block lets held jobs board, and removing the station fails its jobs as for any removed station. A job already riding is never held (admission looks at waiting entries only).
8. **Escalation** is a human ask on the **pipeline run**: a gate of the new kind `admission`, with `stepId` = the station and a new `jobId` field (default null). A pipeline has no manager, so only the panel decides it (`resume` refuses, as for any run it does not manage); the run's status does not change. Choices (`retry` check again, keep holding; `withdraw` the job leaves like a canceled hand-off, its hand-off step ends `failure` and is not retried; `admit` it boards and is `forced`), each with an optional comment. One open ask per job: escalating again opens no second one. The ask closes itself (`dismissed`, no decider) when the job is admitted by the script or ends (settled, failed, withdrawn, station removed). It is listed by `list_gates` (with `jobId`) and shown in "Needs you" like any gate, and `gate.opened`/`gate.decided` fire from the existing scan. `escalate` is the script's call; escalating after N holds stays the script's business.
9. **Events** (public bus, source `pipelines`, the base payload of the other `job.*` events): `job.held` (+ `reason`), `job.admitted` (+ `via: script | human`, `reason`: the human's comment, else null), `job.escalated` (+ `reason`, `gateId`). Recorded in the event log first (`job.held`, `job.admitted`, `job.escalated`, and the domain event `admission.gate_closed`), with reducers and parity as the other job events; the jobs area now owns the pipeline's admission gates as well as its jobs (its genesis state is `{ jobs, gates }`; a genesis written as a plain list of jobs still loads). They are valid `wake_on` types. `event_core.log: false` changes nothing but the files.
10. **Visibility.** `get_run` lists, per job and station, `held: { reason, since, checkedAt }`. The panel's station view shows a "Held" badge with the reason, the time it waits and the last check, and "Admission: checking" or "waiting, next check in ~Ns", plus an alert (message and end of output) when the last check failed. That status is live and in memory (`runs.admission` RPC `{ runId }`, polled every 3 s while jobs wait), like the script live output: empty after a restart until the next check.

## Consequences

- A train still carries a batch with one fate per job; admission only decides who boards.
- A broken script holds everything (a new job stays held until a check works) and says so on the station: this is chosen over boarding unchecked.
- The extra check after a job joins (the first look and its own `job.queued` can both fire) costs at most one more run of the script.
- A station that cannot reach its script because the pipeline's workspace is stale refreshes it between trains; while a train runs, a script added to the branch is not seen until the train ends.
- Not built: a policy to escalate after N holds, a per-station gap, persisting the check status.
