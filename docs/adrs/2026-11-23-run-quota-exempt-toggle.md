# A run can be exempted from quota limiting after it started, from the Runs view or by an agent

Status: Accepted. Refines `2026-11-23-quota-exempt-runs.md` (its "set only at start" rule changes). Follows the conventions of `2026-11-23-run-quota-priority-override.md` (sticky children flag, history, event) and `2026-11-23-run-priority-in-runs-view.md` (the popover).

## Context

A run is exempt from quota limiting only if it was started so. A person who sees a run held (headroom, pace, exhausted window, a cap) that really must run now had no way to say so without cancelling and restarting it.

## Decision

- **Tool and RPC.** `set_run_quota_exempt { runId, exempt, applyToChildren? }` (agent tool, registered with the run tools like `set_run_priority`, so callable by any non-step agent; step agents do not get it) and the `runs.set_exempt` RPC (same input; output `quotaExempt`, `inheritChildExempt`, `from`, `changed`, `cascaded`; used by the Runs view). A finished or archived run, or an unknown one, is refused. Idempotent: the same state again changes nothing, records nothing and emits nothing.
- **Exempt.** The run's `quotaExempt` becomes true and the plugin acts at once, not at the 15 s tick: it runs the quota check for the run (an exempt run gets no hold, so any quota, headroom, pace or cap hold is lifted, with the release the manager is told about when a hold notice had been sent), reads the pace plan again, and runs a tick so the ready steps start. The run keeps reserving its cost for the others, as any exempt run does.
- **Not exempt.** The flag becomes false; the limits apply again from the run's next step. A running step is never interrupted.
- **Children.** A parallel sticky flag `inheritChildExempt` (default false), not the priority's `inheritChildPriority`: the two actions are independent (exempting a run must not rewrite its children's priorities, and a priority change must not exempt anything), and a shared flag would make a call of one kind change the other's later behaviour. `applyToChildren` has the priority's semantics: true copies the state onto every active descendant now (breadth-first, each once, at most 20 levels, so a cycle ends; finished or archived descendants are left alone) and keeps the flag; false clears it without resetting children; omitted keeps it, and while it is on every change (an un-exempt too) is passed down again. A child started later carries the flag on (so its own children follow) and, as before, starts exempt when its parent is exempt. The popover has ONE "Apply to children" checkbox: it keeps its priority meaning (it sends the priority at once, as before) and, when the user has touched it in the same popover, the exempt button sends its state as `applyToChildren` too. Untouched, the exempt call omits it.
- **History and event.** A `quota_exempt_changed` history entry on each run touched (from → to, `by`), and a `run.quota_exempt_changed` event on the edited run: `from`, `to`, `inheritChildren`, `cascaded`, `by` (`agent <id>` or the Runs view). `get_run` shows `quotaExempt` and `inheritChildExempt`.
- **UI.** In the priority popover, below the stepper, Reset and "Apply to children": a button "Run now, ignore quota limits" with a one-line caution ("This run will no longer wait for quota and ignores the Max usable quota."). The first tap turns it into a "Confirm: run now, ignore quota limits" state (inline, no modal; closing the popover cancels it); the second sends. For an exempt run the row shows the existing `exempt` tag, now tappable: it opens the same popover, which shows the exempt state at the top, no stepper (an exempt run's priority is meaningless), "Apply to children" and "Back under quota limits" (one tap, no confirmation: it is the safe direction). The accent colour is used, not red, and not the violet reserved for holds. The Runs view's priority view now exists for every active exempt run, also in a project without pacing (older servers keep the plain tag). The Quota limitation tab already excludes exempt runs from held and paused. Strings in en, fr and zh-CN.

## Consequences

- **An agent can exempt its own run.** The user accepted this risk: any non-step agent may call the tool for any run, including the one it manages, so a manager could skip pacing. It is not hidden: the history entry and the event carry who did it. The warden could later watch `run.quota_exempt_changed` made by an agent on its own run; this ADR does not add that check. If it becomes a problem, a config switch can restrict the tool by a later ADR.
- The `quotaExempt` flag is no longer fixed at start; `restart_run` and `replace_child` keep their rules (the flag stays, a replaced child takes its new parent's).
- An exempted run can push the quota past what pacing allows: that is the point. Others wait for the headroom it leaves.
