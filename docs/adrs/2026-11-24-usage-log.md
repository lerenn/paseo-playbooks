# Per-turn usage log

## Status

Accepted

## Context

Moving mechanical roles to cheaper models needs a simulation over what each turn really consumed.
The plugin already reads every agent's cumulative usage when its turn ends (`recordUsage`) and keeps
per-agent sums in `agent-usage.json`, rewritten whole: no timestamp per turn, no tier, step or
playbook. The tier of a step's agent was resolved away by the loader, so no run knew it.

## Decision

- **A new append-only log**, `<data dir>/usage/usage-YYYY-MM.jsonl` (monthly files, the UTC month of
  the row), one JSON object per line, written by `recordUsage` on every turn end of every daemon
  agent. Writes are serialised through one queue (lines never interleave); a failure is logged once
  and never breaks a turn. Files are never rewritten or deleted by the plugin.
- **Row schema v1** (a turn): `v, ts, agentId, turnSeq, runId, playbook, step, attempt, role, tier,
  provider, model, kind, delta {input, cacheRead, cacheWrite, output}, contextUsed, costUsd, retry`.
  Only counters and identifiers: no prompt, message or tool output. `turnSeq` is the ledger's turn
  count for the agent (restored from `agent-usage.json`). `cacheWrite` is always `null`: the daemon
  does not expose cache-write tokens. `kind` is `step | decider | manager | sidekick | other`;
  coordinators and interactive agents are not told apart (they are `other`).
- **Retry marks** are never edited into a row. A step attempt carries `retry` (`recheck` after a goto
  with a delay, `feedback` after a goto, `interrupted` for a further attempt of a step with no goto)
  and a turn row copies it. When an attempt ends, a separate `{v, type: "attempt_end", ts, agentId,
  runId, step, attempt, outcome}` row is appended, to join on `runId, step, attempt`.
- **Run state**: `attempt.tier` (the tier of the origin when the attempt moves to a fallback target
  or the manager's model; the actual model is on the row), `attempt.retry`, a step state's
  `nextRetry` (set by a goto, consumed by the next attempt) and `run.managerTier`. All optional with
  defaults, so older runs load. `AgentSettings` carries `tier` once resolved (a layer that picks its
  own provider or model without a tier clears it). The playbook YAML format is unchanged.
- `server/usage-log.ts` exports the row types and `readUsageLog(dir, { from, to })`, an async
  iterator over the rows in a time range.

## Consequences

- About 250 bytes per turn, roughly 1 MB a day on a busy daemon; the startup logs the total size at
  debug level. Deleting old months is up to the user.
- A turn is counted when its end hook runs: a turn that ends while the plugin is down is not logged
  (its usage reaches the next turn's delta, as in the ledger).
- A fallback or manager-chosen model is visible only through `provider/model` of the row; its tier
  is the origin's. Gate deciders have no tier on their rows.
- `costUsd` is only set when the daemon reports a cost (see *Data quality*).

## Data quality

- **Cost**: the last cumulative `totalCostUsd` of each agent is kept in its `agent-usage.json` entry
  (`last.totalCostUsd`, optional, so older files load), next to the token reading, and survives a plugin
  restart. `costUsd` is the difference with it; a total that went down (the session's counter restarted)
  counts as its new value, as for tokens. It is `null` when the turn reports no cost, and for the first
  turn of an agent whose ledger entry predates this field (the baseline is unknown, not guessed). The
  daemon's `sessionMetrics` is not typed in the pinned plugin SDK, so it is not read.
- **Provider and model** of a row come from the agent snapshot (`agent.provider`, `agent.model`), which
  is the actual target whatever the run resolved (fallback or manager-chosen models included). Only
  `attempt_end` rows carry no provider or model by design: they are not turns.
- The row schema is unchanged (v1, same keys).
